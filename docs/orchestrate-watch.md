# orchestrate-watch — ночной сторож очереди GLM

`bin/orchestrate-watch` (`common/orchestrate-watch.template.sh`) — держит очередь
проекта работающей без человека. Родился в ночь 13→14.10.2026 на очереди
`kso_loyalty_dorabotki_20261014` (задача: максимум работы за ночь при квоте,
которая может кончиться).

## Зачем

Оркестратор честно (fail-closed, `--quota-policy enforce`) останавливается при
исчерпании квоты или смерти воркера. Без сторожа простой до утра никто не
заметит. Сторож пережидает сброс 5-часового квотного окна и перезапускает
очередь сам.

## Что делает

1. Каждые `WATCH_INTERVAL_SECONDS` (умолчание 600 с) проверяет: есть ли в
   `tasks/` таски `T*.md` без терминальной строки `STATUS:` в
   `reports/report_<ID>.md`. Все закрыты → пишет сводку в лог и завершается.
2. `bin/orchestrate status` = RUNNING → ничего не делает.
3. Очередь встала → читает квоту `five_hour` из `bin/orchestrate limits`:
   - осталось ≥ `WATCH_MIN_QUOTA_PERCENT` (умолчание 15%) → перезапускает
     `orchestrate start` (те же controller/max-parallel/quota-policy);
   - мала → ждёт следующего цикла (окно катящееся, сбрасывается само).
4. Анти-шторм: не больше `WATCH_MAX_RESTARTS` (умолчание 8) перезапусков за
   жизнь; при исчерпании — останавливается и пишет в лог, очередь не трогает.

Ничего не теряется: частичные правки живут в worktree-ветке проекта, коммиты —
в git, отчёты со `STATUS:` — в `reports/`; перезапуск продолжает с места
остановки (таски идемпотентны по `STATUS:`).

## Запуск

```bash
cd /work/glm
tmux new-session -d -s glm_watch_<проект> \
  "bin/orchestrate-watch --project /work/glm/tasks/<проект>"
tail -f /work/glm/tasks/<проект>/logs/orchestrate-watch.log
```

Один проход без цикла (проверка/тест): `WATCH_ONCE=1 bin/orchestrate-watch
--project ...`.

## Параметры (env)

| Переменная | Умолчание | Смысл |
|---|---|---|
| `WATCH_INTERVAL_SECONDS` | 600 | период проверки |
| `WATCH_MAX_RESTARTS` | 8 | потолок перезапусков за жизнь сторожа |
| `WATCH_MIN_QUOTA_PERCENT` | 15 | порог остатка квоты для перезапуска |
| `WATCH_CONTROLLER` | manual | контролёр очереди |
| `WATCH_MAX_PARALLEL` | 1 | параллель воркеров |
| `WATCH_START_ARGS` | — | доп. аргументы `orchestrate start` |
| `WATCH_ONCE` | 0 | 1 = один проход и выход |
| `WATCH_LOG` | `<проект>/logs/orchestrate-watch.log` | лог |

## Чего он НЕ делает

- Не перезапускает задачу с терминальным FAIL/BLOCKED по кругу (перезапуск
  только пока есть таски без `STATUS:`; карантин/статусы — зона оркестратора).
- Не поднимает очередь, если её никто не объявлял: сторож лишь перезапускает
  уже стартовавший проект.
- Не обходит квоту: при малом остатке ждёт, как и оркестратор (fail-closed).
