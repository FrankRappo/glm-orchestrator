ИНТЕРАКТИВНЫЙ ДИАЛОГ С GLM В WSL
================================

В этой установке ZCode CLI 0.16.9 команда "glm tui" не запускается:
отсутствует пакет @zcode/tui. Поэтому в репозитории есть bin/glm-chat —
терминальный диалог поверх штатных команд "glm --prompt" и "--resume".
Скрипт сохраняет контекст между репликами через session ID, но это простой
текстовый интерфейс, а не полноэкранный Codex TUI. Новые зависимости не нужны.

1. Проверить установку и доступ к модели

   Однократно направьте короткую команду glm на диспетчер этого проекта
   (в этой системе ссылка уже настроена):

     sudo ln -sfn /work/glm/bin/glm /usr/local/bin/glm

   Теперь "glm" без аргументов открывает диалог, как команда "codex".
   Подкоманды и параметры нативного CLI (например, --prompt, doctor,
   login, --version) продолжают работать через прежний glm-linux.

   В WSL/Ubuntu выполните:

     glm --version
     /work/glm/bin/orchestrate doctor --live
     /work/glm/bin/orchestrate limits

   Нужны установленный ZCode CLI и авторизованная учётная запись Z.AI.
   Если doctor сообщает об отсутствии авторизации, выполните "glm login"
   под обычным пользователем WSL. Для GLM не нужен ключ DeepSeek.

2. Начать новый диалог (режим планирования)

     cd /work/my-project
     glm

   Либо из любого каталога:

     glm chat --project /work/my-project

   Замените /work/my-project на существующий каталог. Обычно без --project
   используется текущий каталог терминала. Если root запускает glm из
   каталога, недоступного обычному пользователю WSL, используется /work.
   После "You>" печатайте запрос
   и нажимайте Enter; после "GLM>" можно отправлять следующий запрос.
   Сессия и контекст сохраняются между репликами. /exit завершает диалог.

   По умолчанию выбран "plan": из вызовов исключены Bash, Edit и Write.
   Это режим для обсуждения и анализа, а не для изменения файлов.

3. Дать GLM возможность менять файлы

     glm chat --project /work/my-project --mode yolo

   ВАЖНО: headless-режим ZCode не поддерживает интерактивное подтверждение
   действий. В "yolo" агент может выполнять команды и менять файлы БЕЗ
   запросов разрешения. Запускайте только в доверенном проекте, лучше в
   отдельной Git-ветке, и проверяйте diff и тесты после работы. Это не тот
   же уровень контроля, что у Codex с запросами подтверждения.

4. Вернуться к разговору позже

   При выходе glm-chat печатает идентификатор sess_... и готовую команду.
   Продолжить последний диалог в каталоге проекта:

     glm chat --project /work/my-project --continue

   Продолжить конкретный диалог:

     glm chat --project /work/my-project --resume sess_...

   Для работы с файлами при продолжении снова явно добавьте --mode yolo.
   Локальную историю сессий хранит ZCode в профиле пользователя WSL;
   она не включена в Git-репозиторий. При запуске команды от root штатная
   обёртка запускает сам ZCode под обычным пользователем hgff, чтобы
   использовать его авторизацию. Это не даёт GLM прав root на файлы проекта.

5. Отличие от оркестратора задач

   "glm"/"glm chat" — разговор с человеком, один запрос за раз.
   "bin/orchestrate start" — автономная очередь задач в tmux. Команда
   "orchestrate attach" показывает работу очереди, но не заменяет чат.

6. Если не работает

   - "GLM CLI not found": проверьте, что команда glm есть в PATH.
   - Ошибка входа: выполните "glm login" и затем doctor --live.
   - Нет ответа: проверьте сеть и квоты командой "bin/orchestrate limits".
   - Если GLM завершил реплику с ошибкой, glm-chat не повторяет её
     автоматически: перед повтором проверьте состояние файлов.
   - После исправления пакета @zcode/tui можно попробовать официальный
     полноэкранный интерфейс: glm tui --cwd /work/my-project.
